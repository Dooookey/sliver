## 1. 仓库布局与分支策略

两个仓库：

| 仓库 | 内容 | 远端 |
|---|---|---|
| `sliver`（现有 fork） | 官方 Go 代码 + `server/cppbuild` + `server/rpc/rpc-generate-cpp.go` + `implant-cpp/`（当前内联） | `Dooookey/sliver` |
| `implant-cpp`（新建） | 仅 C/C++ implant 工程（CMake 工程、tests、CI） | `<you>/sliver-implant-cpp` |

拆分方式（保留完整提交历史，已在本机执行完成）：

```powershell
pwsh -File scripts/split-implant-repo.ps1 -Target D:\GOPATH\src\C2\implant-cpp
# 然后在 GitHub 建空仓库（不要 README/licence），再：
git -C D:\GOPATH\src\C2\implant-cpp remote add origin git@github.com:<you>/sliver-implant-cpp.git
git -C D:\GOPATH\src\C2\implant-cpp push -u origin main
```

**当前状态**：两个仓库都已推送。

| 仓库 | 分支 / tag | 说明 |
|---|---|---|
| `Dooookey/sliver` | `feat/implant-cpp` | `server/cppbuild`、`rpc-generate-cpp.go`、`generate-cpp`、`.run/`、`docs/refactor/01–07`，`implant-cpp` 已切成 submodule |
| `Dooookey/sliver-implant-cpp` | `main` / `dev`，tag `v0.1.0-p0` | 独立 CMake 工程 + CI（linux gcc/clang、mingw、msvc），可单独 clone 构建 |

接线方式：`sliver/.gitmodules` → `implant-cpp = https://github.com/Dooookey/sliver-implant-cpp.git`。
改 C/C++ 时在 submodule 里提交并 push，然后回主仓 `git add implant-cpp` 提交指针（这是 submodule 的标准流程）。
`sandbox` 下 `git subtree` 需要放宽权限（它依赖 MSYS shell 创建管道），脚本已改为静默处理 git 的 stderr 进度输出。

拆分后二选一保持联动：

- **A（推荐）submodule**：`sliver` 里把 `implant-cpp` 换成 submodule，`cppbuild` 仍然从 `implant-cpp/` 目录构建，GoLand 里也能直接浏览；
  ```powershell
  git -C sliver rm -r --cached implant-cpp
  git -C sliver submodule add https://github.com/<you>/sliver-implant-cpp.git implant-cpp
  git -C sliver commit -m "chore: use implant-cpp as submodule"
  ```
- **B subtree push**：继续在 `sliver/implant-cpp` 里开发，推送到独立仓：
  ```powershell
  git -C sliver subtree push --prefix=implant-cpp <remote> main
  ```

分支约定（两仓一致）：

| 分支 | 用途 |
|---|---|
| `main` / `master` | 可发布；`GenerateCpp` 默认从这里构建 |
| `feat/**` | 功能分支（当前 `feat/implant-cpp`） |
| `proto/**` | 协议对齐/金标向量相关改动 |

CI：`implant-cpp/.github/workflows/ci.yml` 已就绪（linux gcc/clang、mingw 交叉、msvc 三组，含**静态性 + 体积门禁**）。
推到独立仓后自动生效；`sliver` 仓的 Go 侧沿用官方 workflow。

## 2. 在 GoLand 里调试 sliver（server / client）

### 2.1 一次性准备

```powershell
# 1) Go 版本（仓库 go.mod 要求 1.27.1+）
go version          # 需 >= 1.27.1

# 2) 生成 server 依赖的内嵌资源（否则 server 包编译报 assetsFs undefined）
cd D:\GOPATH\src\C2\sliver
go generate ./server/assets     # 或 ./go-assets.sh（会解包 go/zig/garble 资产，第一次较慢）

# 3) protobuf 插件在 PATH 上（你的机器在 D:\GOPATH\bin）
$env:PATH = 'D:\GOPATH\bin;' + $env:PATH
protoc-gen-go --version         # v1.36.12
protoc-gen-go-grpc --version    # 1.6.2
```

> `make pb` 用的是 `protoc -I protobuf/ ...` 五条命令，Windows 没 make 时直接照抄 Makefile 里的五条也行；
> 本次 `services.proto` 的 `GenerateCpp` 已经用同一组插件生成好了（`services.pb.go` / `services_grpc.pb.go`）。

### 2.2 运行/调试配置（已随仓库提交）

`.run/` 下三个共享配置（GoLand 打开项目后自动出现在运行下拉框）：

| 文件 | 作用 |
|---|---|
| `.run/sliver-server.run.xml` | `go run -mod=vendor -tags server ./server`，工作目录 = 仓库根 |
| `.run/sliver-client.run.xml` | `go run -mod=vendor -tags client ./client` |
| `.run/cppbuild-tests.run.xml` | `go test ./server/cppbuild` |

启动 server 后在 `generate.GenerateConfig` / `cppbuild.compile` 里下断点，从 client 执行
`generate-cpp --mtls 127.0.0.1:8888` 就能单步跟踪到「写 config.json → 调 cmake → 校验产物」全过程。

### 2.3 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `undefined: assetsFs` | 没跑 `go generate ./server/assets`（见 2.1） |
| **能编译、但调试启动即退出 / 没有 sliver 命令界面** | **运行配置的 build tags 少了 `go_sqlite`**：server 需要 `go_sqlite,server`，client 需要 `go_sqlite,client`。少了它 `assetsFs`/`sqliteClient` 未定义（旧配置就是这个问题，已修） |
| 调试 server 时控制台空白 / TUI 不起来 | server 默认是 bubbletea TUI，dlv 的控制台不是 TTY。两种解法：① 运行配置勾选 “Emulate terminal in output console”（`.run` 里已带 `EMULATE_TERMINAL`）；② 自己建一个 daemon 配置（Program arguments 填 `daemon`，见 §8.3），跑无界面 daemon，再从 `sliver-client (console)` 或编译好的 `sliver-client.exe` 连上去操作 |
| 运行配置显示「配置已损坏」 | `.run/*.xml` 里有 JetBrains 不认识的元素（之前提交的 daemon 配置用了 `program_parameters`，已删除）。在 GoLand 里删掉该条目，按 §8.3 用 UI 重建 |
| `mkdir ...\go-build: Access is denied` | GoLand 的 `GOCACHE` 指到了不可写目录；Settings → Go → Build Tags & Vendoring 里加环境变量 `GOCACHE=D:\GOPATH\go-build` |
| `cmake not found` | GoLand 运行配置默认继承系统 PATH；确认 `cmake` 在 PATH（你已装 3.31） |
| `implant-cpp source dir not found` | 从非仓库根目录启动；或在 Run 配置里设 `SLIVER_CPP_SRC=<仓库>\implant-cpp` |
| server 启动后连不上 implant | mtls 端口/证书：`generate` 时 `--mtls` 必须与 server 监听一致（默认 8888） |

### 2.4 用 `generate-cpp` 生成 C implant（已打通）

**独立的 `generate-cpp` 命令**（别名 `gcpp`），不是在官方 `generate` 上打补丁——`client/command/generate` 包与上游 master 完全一致（`git diff master -- client/command/generate` 为空）。
新命令在 `client/command/cppgen`，复用官方的 C2 URI 解析函数（`generate.ParseMTLSc2` 等）与同名字段语义，只把 RPC 换成 `GenerateCpp`：

```text
sliver > generate-cpp --mtls 127.0.0.1:8888 --os windows --arch amd64 --format exe
[info] Generating new windows/amd64 C/C++ implant (EXECUTABLE)
[info] Compiling with cmake, please wait ...
[info] Build completed in 12s
[info] Implant saved to ...\IMPLANT.exe (141,312 bytes)
```

支持的形态：`--beacon` + `--interval/--jitter`（秒）、`--format exe|shared|service|shellcode`（shellcode 由服务端返回明确未实现）、
`--mtls/--http/--dns/--wg/--named-pipe/--tcp-pivot`、`--strategy/--reconnect/--poll-timeout/--max-errors/--c2profile`、`--limit-*`。
Go 专有开关（`--skip-symbols`、`--netgo`、traffic encoders、shellcode encoder、`--external-builder`）**不提供**，避免“静默忽略”。

**产物是自包含的**：`generate-cpp` 把 C2 地址、mTLS PEM、age 私钥、server minisign 公钥等全部写进构建期生成的
`implant_secrets.c`，运行时**不需要任何命令行参数**，直接执行二进制就会回连（等价 Go implant）。验证：

```powershell
pwsh -File tests\scripts\inject-config-selftest.ps1 -Port 9449
# ==> starting from injected config: 127.0.0.1:9449 (mtls://127.0.0.1:9449)
# ==> session: registered as injected-implant (windows/amd64, pid ...)
# 服务端: REGISTER ok: name="injected-implant" ... c2="mtls://127.0.0.1:9449"
```

服务端行为：`GenerateCpp` 复用官方 `generate.GenerateConfig`（密钥/证书/WG/落库记录）与 HTTP C2 profile，
只把编译后端换成 `server/cppbuild`（写 `config.json` → `cmake` → 校验 PE/ELF + 静态性 + 体积）。

后端链路的端到端测试（不需要起 server）：

```powershell
$env:SLIVER_CPP_SRC = "D:\GOPATH\src\C2\sliver\implant-cpp"
go test -tags "go_sqlite,server" -run TestCompileExecutable -v ./server/cppbuild
# 已实测：artifact 141,312 bytes（静态 PE，GUI 子系统），config.json 里保留 C2 URL
```

### 2.5 调试 Go implant 生成链路（对拍用）

同一份配置先用官方 `generate`（Go implant）跑一次，再用 `generate-cpp` 跑一次，
两次的 `~/.sliver/slivers/<os>/<arch>/<name>/` 下产物应能分别在 `sessions` 里出现——
这是「C 实现没有偏离官方逻辑」最直接的验证方式。

## 3. 调试 C/C++ implant

**GoLand 本身不带 C/C++ 调试器**（JetBrains 里这块属于 CLion）。三种可行方式，按省事程度排序：

### 3.1 CLion（推荐，同一套 JetBrains 快捷键）

1. CLion → Open → 选 `implant-cpp/CMakeLists.txt`（或整个目录）；
2. Settings → Build, Execution, Deployment → CMake → 选 preset `msvc-x64-debug`（Windows）或 `wsl-gcc-debug`（WSL）；
3. 运行配置选目标 `implant`，断点直接下在 `src/core/config.c`、`src/platform/win32/thread.c`；
4. WSL 调试：Settings → Toolchains → 添加 WSL（Ubuntu），CMake preset 选 `wsl-gcc-debug`，调试器用 `gdb`（WSL 里已有 `/usr/bin/gdb`）。

### 3.2 VS Code / Visual Studio

- VS Code：装 `CMake Tools` + `C/C++`，选 preset `msvc-x64-debug` / `wsl-gcc-debug`（Remote-WSL），F5 直接起 `cppdbg`；
- Visual Studio 2022：`File → Open → Folder` 打开 `implant-cpp`，VS 会自动读取 `CMakePresets.json`，选 `msvc-x64-debug` 后 F5。

### 3.3 纯命令行（无 IDE 也能调）

```bash
# Linux / WSL
cmake --preset wsl-gcc-debug && cmake --build --preset wsl-gcc-debug
gdb -q ./build/wsl-gcc-debug/bin/implant
(gdb) b sliver_config_self_check
(gdb) run
```

`wsl-gcc-debug` 预设刻意关闭了 `-static`（`IMPLANT_STATIC_LINK=OFF`）并保留 `-g3`，方便 gdb/lldb 单步；
发布构建仍用 `wsl-gcc`（静态 + strip）。

### 3.4 关键调试点

| 场景 | 位置 | 观察 |
|---|---|---|
| 配置注入是否正确 | `sliver_config_self_check()`（`src/core/config.c`） | 返回 0 且 `sliver_config_c2_url(0)` 是 server 下发的 URL |
| 密钥槽是否齐全 | `sliver_config_secret(SLIVER_SECRET_PEER_PRIVATE_KEY)` | 非 NULL；长度与 age 私钥串一致 |
| 后续协议层 | `src/wire/*`、`src/transport/tls_client.c` | 见 §3.5 |

### 3.5 TLS 1.3 握手自测（P0.5，已打通）

对着一个 Go 写的 mTLS 测试服务端跑真实握手（TLS1.3 only、`RequireAndVerifyClientCert`、客户端证书 P-521）：

```powershell
cd D:\GOPATH\src\C2\sliver\implant-cpp
pwsh -File tests\scripts\tls-selftest.ps1 -Config msvc-x64-debug
```

预期输出：

```
==> building the Go TLS fixture server
==> starting ...\build\msvc-x64-debug\tls-testserver.exe on 127.0.0.1:9443
==> handshake
handshake ok: TLSv1.3 / TLS1-3-CHACHA20-POLY1305-SHA256
echo (22 bytes): MUX/1sliver-cpp hello
==> handshake selftest passed
```

服务端日志：`handshake ok: version=TLS 1.3 cipher=TLS_CHACHA20_POLY1305_SHA256 client-cert=sliver-cpp test client`。

**VS2022 单步断点**：

| 位置 | 观察 |
|---|---|
| `src/transport/tls_client.c` → `sliver_tls_connect` | 证书/私钥解析、`ssl_config_defaults`、`min/max_tls_version`、`conf_own_cert` |
| 同文件 `verify_chain_only` | 只验链到内置 CA，`*flags = 0` 忽略主机名 |
| 同文件 `mbedtls_ssl_handshake` 循环 | 握手推进与 `WANT_READ/WANT_WRITE` |
| `src/platform/win32/net.c` | `sliver_tcp_connect` / `send` / `recv` |

手动方式：

```powershell
.\build\msvc-x64-debug\tls-testserver.exe -addr 127.0.0.1:9443 -out build\tls-fixtures
.\build\msvc-x64-debug\bin\implant.exe --tls-selftest 127.0.0.1 9443 `
    build\tls-fixtures\ca.pem build\tls-fixtures\client.pem build\tls-fixtures\client.key
```

Linux/WSL 用 `tests/scripts/tls-selftest.sh`（`CONFIG=wsl-gcc-debug`）。

## 8. 操作速查（GoLand / VS2022）

### 8.1 拉代码 + 初始化 submodule（在哪个目录执行）

**在 `D:\GOPATH\src\C2\sliver` 下执行**（这个目录里有 `.git` 和 `.gitmodules`；不要在 `implant-cpp` 子目录里执行 submodule 命令）：

```powershell
cd D:\GOPATH\src\C2\sliver

git pull                                  # 拉 feat/implant-cpp 最新提交
git submodule sync --recursive
git submodule update --init --recursive   # 首次：把 implant-cpp 从 GitHub 克隆到 ./implant-cpp

# 校验
git log --oneline -1
git submodule status                      # 应显示 4754028... implant-cpp (v0.1.0-p0)
dir implant-cpp\CMakeLists.txt            # 应存在
```

以后每次 `git pull` 后如果 `git submodule status` 前面出现 `+` 或 `-`（指针落后/未初始化），再跑一次 `git submodule update --init --recursive`；
在 `implant-cpp` 里改代码则是「进 submodule 提交 → push → 回主仓 `git add implant-cpp` 提交指针」。

### 8.2 Build Tags 设置在哪里

GoLand 2024/2025 的路径：**Settings → Go → Build Tags & Vendoring**（旧版本同位置；有的版本把它放在 `Go` 节点下的 `Build Tags`）。
把 **Build tags** 填成：

```
go_sqlite,server
```

找不到该页时的两种等价做法：

1. **每个运行配置里加 Go tool arguments**（`.run/*.xml` 里已经写了 `-mod=vendor -tags go_sqlite,server`，所以用仓库自带配置时无需再设）；
2. **设环境变量** `GOFLAGS=-tags=go_sqlite,server`（作用于整个项目；客户端调试时改成 `go_sqlite,client`）。

判断是否生效：打开 `server/assets/assets_windows_amd64.go`，若 `assetsFs` 不再标红、`go build ./server` 能过，就对了。

### 8.3 自己建一个 daemon 调试配置（避免 XML 手工写坏）

之前提交的 `sliver-server-daemon.run.xml` 用了 GoLand 不认识的 `program_parameters` 元素，所以显示「配置已损坏」，该文件已删除。
需要无 TUI 的调试方式时，用 UI 建（GoLand 生成的 XML 一定合法）：

1. Run → Edit Configurations… → `+` → **Go Build**（Go Application）；
2. Name 填 `sliver-server (daemon)`；
3. Run kind 选 **Package**，Package path 填 `github.com/bishopfox/sliver/server`；
4. Working directory 填 `D:\GOPATH\src\C2\sliver`；
5. **Program arguments** 填 `daemon`；
6. Go tool arguments 填 `-mod=vendor -tags go_sqlite,server`；
7. Environment 里加 `CGO_ENABLED=0`；
8. OK 后在 Debug 模式下启动。

> daemon 模式没有 TUI，断点、变量、调用栈都正常；用 `sliver-client (console)` 或你已有的 `sliver-client.exe` 连上去操作。
> 想调 TUI 本身，就用 `sliver-server (console)` 配置并勾选 **Emulate terminal in output console**。

### 8.5 常见现象对照

| 现象 | 处理 |
|---|---|
| **generate-cpp 产物双击/运行没反应** | ① 旧版本 GUI 入口传了 `argc=0`，导致无参自启动分支根本没执行（已修）；② `--debug` 构建会保留控制台并写 `%TEMP%\sliver-implant.log`，用它定位；release 构建按设计**完全静默**（无窗口、无日志）；③ 用 `implant.exe --version` 确认产物是否真的链上了加密层（见下） |
