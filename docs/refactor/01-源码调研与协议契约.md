## 2. 运行模型

### 2.1 入口与形态（模板化）

`main.go` 是模板：`{{if .Config.IsSharedLib}}` 决定是否 `import "C"`，`{{range .Config.Exports}}` 生成 `//export <Name>` 幂等包装（`main.go:23-45`）。
`main.c` 按平台提供入口：Windows `DllMain` + `CreateThread(Start)`（`main.c:16-44`，注释明确不能在 DllMain 内联做网络）、
Linux `.init_array`（`main.c:52-60`，先 `unsetenv("LD_PRELOAD")`）、macOS constructor（`main.c:66-73`）。
**结论**：产物形态是一等构建输入，C 工程必须显式建模（`IMPLANT_FORMAT=exe|shared|shellcode`），不能靠调用方自觉。

### 2.2 session 主循环（`runner/runner.go:621-742`）

1. `connection.Start()`（建立传输）→ 发送 `MsgRegister(1)` + `Register`（`runner.go:642-647`）；server **不回包**。
2. 进入 `for` 循环：从 `connection.Recv` 或 `connection.Done()` 取事件。
3. 分发表优先级：`killHandlers`(命中即终止) → `pivotHandlers` → `rportfwdHandlers` → `sysHandlers` → `tunnelHandlers` → `MsgCloseSession` → 未知类型回 `UnknownMessageType:true`（`runner.go:669-739`）。
4. 所有 handler 都 `go` 到新协程，回包通过 `connection.SendEnvelope(&Envelope{ID: 原ID, Data: resp})`（`runner.go:697-720`）。
5. Windows 上每个 RPC 前重新 `ImpersonateLoggedOnUser` 并锁 OS 线程（`handlers/handlers_windows.go:143-163`）——C 侧需线程绑定语义。

### 2.3 beacon 主循环（`runner/runner.go:244-430`）

1. `beacon.Init()` → `Start()` → 发 `MsgBeaconRegister(93)` + `BeaconRegister{ID, Interval, Jitter, Register, NextCheckin}` → `sleep 1s` → `Close()`（`runner.go:277-288`）。
2. 每轮 check-in：发 `MsgBeaconTasks(94)` + `BeaconTasks{ID, NextCheckin, Tasks: 已完成结果}`。
   - **带结果时不再 Recv，本轮结束**（`runner.go:367-372`，server 对结果-only 的 check-in 不回包）。
   - 无结果时才 `Recv()` 一次，解析 `BeaconTasks.Tasks` 并派发（`runner.go:376-429`）。
3. 任务并发执行，每个完成即 `<Envelope{ID: taskID, Data: result}>` 入队，下一轮统一上报（`runner.go:433-490`）。
4. 节奏：`Duration = Interval + rand(0, Jitter)`（`transports/beacon.go:109-122`），check-in 严格串行不重叠（`runner.go:298-331`）。
5. 退出：`connectionErrors > MaxConnectionErrors`（默认 1000，`transports/transports.go:216-222`）。

### 2.4 容错基线

| 项 | 值 | 证据 |
|---|---|---|
| 重连间隔 | 固定 60s（无指数退避），可运行时 `SetReconnectInterval` | `transports/transports.go:160-170`、`runner.go:169-206` |
| 最大连续错误 | 1000 | `transports/transports.go:216-222` |
| mtls/wg 心跳 | 每 120s 发 `Ping{Nonce:31337}`（单向，server 不回） | `transports/mtls/mtls.go:51,173-185` |
| pivot 心跳 | 每 60s 双向 `MsgPivotPeerPing` / `MsgPivotServerPing` | `transports/session.go:983-1007` |
| 发送背压 | `SendEnvelope` 10s 超时丢弃 | `transports/connection.go:32,148-162` |

## 3. 传输层

### 3.1 scheme 表

| scheme | 上线方式 | 连接前置 | 复用层 | 信封封装 | 默认端口 |
|---|---|---|---|---|---|
| `mtls` | `tls.Dial` + 客户端证书 | 写 `MUX/1`(5B ASCII) | yamux client | `[74B sig][u32 LE len][protobuf]` | 8888 |
| `wg` | 用户态 WG + netstack TCP | 隧道内 TCP 到 `100.64.0.1:1337` 取密钥 → 重连 `:8888` → 写 `MUX/1` | yamux client | 同 mtls | 53（外层 UDP） |
| `http(s)` | HTTP/1.1 POST/GET 长轮询 | 先 POST age 密文换 session id + cookie | 无（请求即信封） | `encode( ChaCha20Poly1305(gzip(Envelope)) )` | 443/80 |
| `dns` | A 查询上行 / TXT-AAAA 下行 | 先 `INIT` 交换会话密钥 | 无（分片+manifest） | 同 http，再 base32/base64 进域名 | 53 |
| `tcppivot` | `net.Dial` | `PivotHello` 双向 age 交换 | 无（`[u32 LE len][双层加密 Envelope]`） | 先 server 后 peer 两层 | 自定义 |
| `namedpipe` | `winio.DialPipe` | 同 tcppivot | 无 | 同 tcppivot | — |

beacon 模式只支持 `mtls / wg / http(s) / dns`（`transports/beacon.go:150-180`）；`namedpipe`、`tcppivot` 仅 session。

### 3.2 mTLS 细节（一期主战场）

- TLS：客户端证书来自 build 期注入的 PEM（`transports/mtls/mtls.go:57-61`），`InsecureSkipVerify=true` + 自定义 `VerifyPeerCertificate` **只验链到内置 CA、跳过主机名**（`mtls.go:285-292`、`cryptography/crypto.go:256-288`）。
- **server 端强制 TLS 1.3**（`server/c2/mtls.go:459`）、`RequireAndVerifyClientCert`；implant 证书曲线可能是 **P-521/P-384/P-256 随机**（`server/certs/certs.go:146-154`）→ C 侧 TLS 栈必须支持 P-521。
- 无 ALPN、不发 SNI 依赖（默认填 hostname 但不校验）。
- yamux：`MUX/1` 前导后进入 yamux，`protoVersion=0`、12B 头 `[ver:1][type:1][flags:2 BE][streamID:4 BE][length:4 BE]`、初始 stream window 256KiB、keepalive 30s（`vendor/github.com/hashicorp/yamux/const.go:81-147`、`mux.go:62-75`）。
- **一条 Envelope 独占一条 stream**（open→写→close），server 每 stream 只读一帧（`transports/session.go:344-357`、`server/c2/mtls.go:232-262`）。
- 并发配额：发送信号量 64、接收 stream 信号量 128（`session.go:327,405`）。

### 3.3 HTTP(S) 细节

| 动作 | 请求 | 期望 | 证据 |
|---|---|---|---|
| 建会话 | `POST <random path>`，body=`encode(digest32‖age_ct)` | 200 + 加密 session id + `Set-Cookie` | `httpclient/httpclient.go:372-434` |
| 收消息 | `GET <random path>` | 200(有包)/204(超时)/403(会话失效) | `httpclient.go:437-494` |
| 发消息 | `POST <random path>`，body=`encode([nonce12]‖ct‖tag)` | 202 | `httpclient.go:497-556` |
| 关会话 | `GET <random path>` | 202 | `httpclient.go:567-609` |

- **Cookie 必须全收全发**（忽略 domain/path/secure），会话即 cookie 值（`httpclient/gohttp.go:117-149`、`server/c2/http.go:866-881`）。
- nonce：随机 uint64 的十进制串，可插入 0~2 个非数字字符，放 path 段或 query；`nonce % 65537 = encoderID`（`httpclient.go:201-231`、`encoders/encoders.go:44-46`）。
- 内置编码器：自定义字母表 base64（`encoders/base64.go:26`）、base32（`encoders/base32.go:27-29`）、hex、english、gzip、png；WASM traffic encoder 暂不支持（C 侧一期只做内置 5 种）。
- 路径每次随机（`MinPathLength..MaxPathLength` 段 + `filename.ext`），profile 头/参数按 `Probability` 掷骰（`httpclient.go:265-319,621-674`）。
- 连接几乎不复用（`IdleConnTimeout=1ms`，`gohttp.go:50,57`）；TLS 侧 `InsecureSkipVerify`，server 会随机化 JARM（`server/c2/http.go:265-337`）→ C 侧不要 pin cipher/版本。

### 3.4 DNS 细节

- 报文：`dnspb.DNSMessage{Type, ID, Start, Stop, Size, Data}`；`ID = (seq%255)<<24 | 24bitSessionID`（`dnsclient/dnsclient.go:1049-1056`）。
- 上行 A 查询：protobuf → 自定义 base32（`ab1c2d3e4f5g6h7j8k9m0npqrtuvwxyz`）→ 63 字符标签，子域预算 `254 - len(parent) - (1 + (254-len(parent))/64)`（`dnsclient.go:69-74,169,560-584`）。
- 下行：TXT（自定义 base64，`MaxTXTLength=254` 切片）或 AAAA（16B 分块，`ttl = msgLen ^ (chunkIdx<<8)` → **单条消息 ≤255 字节**）（`resolver-generic.go:141-205`、`server/c2/dns.go:1040-1069`）。
- 流程：`INIT` → `POLL` → `MANIFEST`(Size) → 并行拉 `DATA_TO_IMPLANT`（TXT 182B/AAAA 192B 一片）→ `CLEAR`。
- 每次成功读后 `sleep 250ms`（`transports/session.go:893`）。

### 3.5 pivot

- 帧：`[u32 LE len][payload]`，上限 512MiB（`pivotclients/pivotclient.go:209-280`、`pivots/pivots.go:46`）。
- 双层：`peerCipher.Encrypt(Envelope{Type:MsgPivotPeerEnvelope, Data: PivotPeerEnvelope{... Data: serverCipher.Encrypt(Envelope)}})`；ping 只做 peer 层（`pivotclient.go:289-408`）。
- 密钥交换：`PivotHello{PublicKey, PeerID, PublicKeySignature}` → 验 minisign 文本签名 → age 解对端会话密钥；同时生成自己的 server 会话密钥，经 `MsgPivotServerKeyExchange` 绕回 server 换取 16B pivot UUID，读超时 5 分钟（`pivotclient.go:76-203`）。

## 4. 加密与签名

### 4.1 会话密钥（http/dns）

`implant` 本地生成 32B 随机会话密钥（`SHA256(64 random)`，`cryptography/crypto.go:118-130`），通过 age(X25519) **单向寄送**给 server：

```
payload = HTTPSessionInit{Key} 或 裸 32B
blob    = HMAC-SHA256(SHA256(agePrivString), payload) ‖ payload      # 32B 前缀
ct      = age_X25519_encrypt(serverAgePub, blob) 且剥掉 32B 固定头前缀
msg     = SHA256(agePubString)[32] ‖ ct
```

证据：`cryptography/implant.go:101-128`、`crypto.go:50,71-115`、server 侧 `server/cryptography/cryptography.go:169-196`。
注意：**密钥派生用的是「age 密钥字符串」的 SHA256，不是原始 32B 密钥**；公钥 digest 同理。

### 4.2 信封 AEAD

| 项 | 值 | 证据 |
|---|---|---|
| 算法 | ChaCha20-Poly1305（IETF，key32/nonce12/tag16，AAD 空） | `crypto.go:134-168` |
| nonce | 每条消息 **12B 随机**（非计数器） | `crypto.go:141-144` |
| 线格式（implant→server） | `[nonce12][ct‖tag]`，**无签名前缀** | `httpclient.go:511` |
| 线格式（server→implant） | `[74B rawSig][nonce12][ct‖tag]` | `server/cryptography/cryptography.go:268-280` |
| 明文预处理 | **先 gzip(BestSpeed)，再加密** | `crypto.go:139-140,167` |
| 重放防护 | 进程内 `SHA256(ciphertext)` 去重 | `crypto.go:212-218` |

### 4.3 minisign / ed25519 方向性签名

- raw 签名 74B：`u16 LE algo(0x6445 EdDSA / 0x4445 HashEdDSA) ‖ u64 LE keyID ‖ 64B ed25519`；`keyID = LE64(BLAKE2b-256(pub)[:8])`（`cryptography/minisign.go:51,175-188`）。
- mTLS/WG 的**出站**签名私钥由 age 私钥派生：`seed = SHA256("env-signing-v1:" + agePrivString)` → `Ed25519(seed)`（`transports/mtls/mtls.go:63,76-95`）；server 侧遍历 build 反查 keyID（`server/c2/mtls.go:73-105`）。
- server→implant 用 **server 的 minisign 公钥**验证，keyID 必须匹配。
- 关键坑：BLAKE2b 必须是**参数化输出 32 字节**（不能用 BLAKE2b-512 截断），否则 keyID 不符、server 直接拒收。

### 4.4 TLS/WG

- mTLS 用 build 期注入的客户端证书；server CA 校验客户端链，客户端只校验「由内置 CA 签发」。
- WG：编译期静态 `WGImplantPrivKey/WGServerPubKey`（hex 小写），运行期经隧道内 TCP 明文 KEX 取 `priv|pub|tunIP`（`transports/wireguard/wireguard.go:410-448`、`server/c2/wireguard.go:209-238`），随后 Noise IK 由 wireguard-go 完成。

## 7. server 侧对接点（现状）

> 位置说明：该原型目前只存在于本地 `sliver-1.7.8` 工作副本，fork `Dooookey/sliver` 的 master 上还没有；M0 第一步就是把它迁进 fork 的 `feat/implant-cpp` 分支。

`server/rpc/rpc-generate-cpp.go`（已有原型）：
1. 复用 `generate.GenerateConfig` 生成 `ImplantBuild`（密钥/证书/WG）。
2. 把 6 个密钥字段 + GOOS/GOARCH 写成 `sliver_config.h`（`rpc-generate-cpp.go:108-131`）。
3. `invokeCMake` 用 `srcDir`（硬编码 `/path/to/your/cpp-implant`）调 CMake（`rpc-generate-cpp.go:133-179`）。
4. `generate.ImplantBuildSave` 落库，返回 `clientpb.Generate`。

**缺口**（本规划要补）：
- 配置不全：无 C2 URL、无 interval/jitter/limits、无 HTTP profile、无 encoder ID、无 Build ID 关联；
- 工具链写死：只有 mingw 与 musl 两个 toolchain 假设，未覆盖 MSVC / clang；
- 无构建缓存与失败诊断：每次全量 configure+build；
- 产物名与格式写死 `implant(.exe)`，不支持 dll/so/shellcode；
- 缺 golden vector 与协议自检，无法验证「生成的产物能回连」。

## 9. 逐字节契约验收表（M1 必须全绿）

**帧与握手**
- [ ] mtls：TCP → TLS1.3（客户端证书、只验 CA 链、跳过主机名）→ 写 `MUX/1` → yamux client
- [ ] yamux：12B 头、字段 BE、protoVersion 0、window 256KiB、**一条 Envelope 一条 stream**
- [ ] 帧：`[74B sig][u32 LE len][protobuf]`，`len>0 && len<=512MiB`
- [ ] 签名：`0x6445` + `keyID=blake2b256(pub)[:8]`(LE) + `ed25519(SHA256("env-signing-v1:"+agePriv))` 私钥签 protobuf 字节
- [ ] http：POST 建会话 200 / POST 发消息 202 / GET 轮询 200·204·403 / GET 关闭 202
- [ ] http：cookie 全收全发；session id 来自「解密响应体」而非 header

**密码学**
- [ ] `gzip(BestSpeed)` → ChaCha20-Poly1305（nonce12 随机前置、AAD 空）
- [ ] implant→server 无签名前缀；server→implant 必须验 74B 前缀
- [ ] age：`HKDF-SHA256(salt=ephPub‖recipientPub, info="age-encryption.org/v1/X25519")`、fileKey 16B、wrap nonce 全零、头部裁剪 32B
- [ ] BLAKE2b **参数化 32 字节**输出；base64 raw-std；bech32（非 m）大小写规则
- [ ] `Envelope.ID` 用 `int64`，回包原样带回；应答 `Type=0`

**行为**
- [ ] beacon：`Duration=interval+rand(0,jitter)`；带结果不等回包；`NextCheckin` 用秒
- [ ] 未知 Type 回 `UnknownMessageType`；`MsgCloseSession` 优雅退出；kill 消息不回复
- [ ] 隧道帧 ≤64KiB、`Sequence` 严格递增、关闭语义按 Capabilities
