# 04 里程碑与验收

> 估算是「1 名熟悉 C/C++ 与网络协议栈的工程师」的人日，不含 UI/文档；不含 WireGuard（单列 M5）。
> 每个里程碑都给出**可执行的验收命令/信号**，避免「写完就算完」。

## M1 协议底座 + mtls 上线（10 人日）

| 任务 | 产出 |
|---|---|
| protobuf 运行时 + codegen（Envelope/Register/Ping/HTTPSessionInit） | `src/proto/*`、`tools/codegen` |
| 加密：SHA256/HMAC/HKDF/X25519/ChaCha20-Poly1305/Ed25519/BLAKE2b-256/base64/base32/bech32 | `src/crypto/*` |
| age 封装（逐字节）+ gzip | `src/crypto/age.c` |
| envelope 帧（74B 签名 + u32 len）+ minisign raw | `src/wire/frame.c` |
| yamux client（stream/window/ping/goaway） | `src/wire/yamux.c` |
| TLS 1.3 客户端（OpenSSL，客户端证书，只验 CA 链） | `src/transport/mtls.c` |
| session 主循环 + register + ping + 重连 | `src/modes/session.c` |

**验收**
```bash
# 起 server（WSL 或 Windows），生成一个 C implant
sliver-server
> generate --mtls 127.0.0.1:8888 --os windows --arch amd64 --format exe --cpp
> sessions                     # 出现 C implant 的会话
> use <id>; ping               # 往返成功
```
- 抓包对比：`tcpdump -w c.pcap` 与 Go implant 同场景对比，TLS 解密后帧结构一致；
- 反向验证：把 server 侧的 `ReadEnvelope` 单测改成读取 C 产物发出的字节（可选）。

## M2 核心 RPC 与隧道底座（15 人日）

| 任务 | 消息 |
|---|---|
| 文件六件套 | `Ls(5)` `Cd(11)` `Pwd(12)` `Download(7)` `Upload(9)` `Rm(14)` `Mkdir(16)` |
| 进程/系统信息 | `Ps(18)` `Ifconfig(42)` `Netstat(49)` `Terminate(45)` |
| 执行 | `Execute(44)`（含 stdout/stderr/Pid/Status） |
| 隧道 | `TunnelData(22)` `TunnelClose(23)` + 序号/窗口/关闭语义 |
| 交互 shell | `Shell(20)` + `ShellResize(135)`（Unix PTY；Windows 走 piped 回退） |
| 生命周期 | `KillSession(4)` `Reconfigure(83)` |

**验收**
```bash
> use <id>
> ls /tmp ; pwd ; cd /tmp ; upload ./a.txt ; download /tmp/a.txt ./b.txt
> ps ; execute -o whoami ; shell        # 进入交互 shell，Ctrl-C 正常
> kill                                  # implant 进程退出且 server 侧会话移除
```

## 每阶段的「不许合并」红线

1. 金标向量回归失败 → 不合并；
2. `strings` 出现绝对路径 / 测试域名 / `bishopfox` → 不合并（CI 卡）；
3. 新增 `#ifdef _WIN32` 出现在 `src/rpc/` 或 `src/wire/` → 不合并（必须下沉到 `platform/`）；
4. 无条件阻塞在 socket 读上而没有 `closed` 打断路径 → 不合并（会导致 kill/重连漏线程）。
