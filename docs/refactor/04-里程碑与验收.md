### P0.4 进展（加密层已落地，TLS 握手为下一步）

| 项 | 状态 |
|---|---|
| 依赖 | `third_party/mbedtls`（官方 **3.6.8 release 源码内联**，含预生成文件，无需 Python/Perl）+ `third_party/ed25519`（orlp，Ed25519-SHA512）+ `third_party/monocypher`（仅 BLAKE2b） |
| 原语 | SHA-256/HMAC/HKDF、ChaCha20-Poly1305（IETF）、X25519（PSA）、Ed25519（seed）、BLAKE2b、bech32、minisign raw 验签、age 封装 |
| 测试 | `tests/unit/test_crypto.c`：RFC 8032 / RFC 7748 / BLAKE2b-512 / ChaCha 往返与篡改 / bech32 大小写 / age 往返；`ctest` 2/2 通过 |
| 待办 | ~~TLS 1.3 客户端~~ **已完成**：`src/transport/tls_client.c` + `src/platform/*/net.c` + `--tls-selftest`；对着 Go 测试服务端（`tests/tls-testserver`）实测 `TLSv1.3 / TLS1-3-CHACHA20-POLY1305-SHA256`，客户端证书为 **P-521**（验证了服务端随机曲线的兼容性） |
| 下一步 | 帧层：74B 签名帧 + yamux client + 最小 protobuf（Envelope/Register/Ping），然后对真 server 注册 |

> 两个踩坑记录（已修）：mbedTLS 的裸 ECP API **不支持 X25519**（Montgomery 曲线），必须走 PSA `psa_raw_key_agreement`；monocypher 的 `crypto_eddsa_*` 是 EdDSA-**BLAKE2b** 变体，与 minisign 不兼容，Ed25519 必须用 SHA-512 实现。

## 每阶段红线（不满足不合并）

1. 金标向量回归失败；
2. 产物非静态（`PT_INTERP` 或 VC 运行时导入）；
3. 体积 > 512 KB 且无 issue 记录原因；
4. `src/rpc|wire|transport` 里出现 `#ifdef _WIN32`；
5. 阻塞读没有 `closed` 唤醒路径（会导致 kill/重连漏线程）。
