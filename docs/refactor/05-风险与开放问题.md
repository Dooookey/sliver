# 05 风险与开放问题（v2）

---

## 1. 兼容性风险（最高优先级）

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 逐字节契约写错（age 头 32B 裁剪、HKDF salt/info、BLAKE2b 输出长度、u32 LE 长度、74B 签名字段序） | 握手被拒，server 侧错误信息极少（HTTP 一律 `ErrDecryptFailed`） | P0 先建金标向量；敏感常量集中 `protocol_const.h` 并附来源注释 |
| R2 | TLS 1.3 参数不匹配（server 强制 1.3、客户端证书曲线可能为 **P-521/P-384/P-256 随机**、无 ALPN） | 握手失败 | mbedTLS 必须开 `MBEDTLS_ECP_DP_SECP521R1_ENABLED` 等三条曲线；三种曲线各生成一次 build 验证；不设 ALPN |
| R3 | yamux 流控偏差（window update、SYN/ACK、keepalive） | 大消息卡死 / 连接被 reset | 移植 `vendor/hashicorp/yamux` 而非重写；用 Go yamux server 做对拍 |
| R4 | protobuf 默认值/未知字段 | server 升级加字段后 C 侧崩 | 强制「跳过未知字段」，所有字段可选；codegen 输出字段号断言 |
| R5 | `Envelope.ID` 用无符号 | 负 ID 回错 → 响应丢失、60s 超时 | 固定 `int64_t`，单测覆盖负数 |
| R6 | beacon「带结果不 Recv」写错 | server 任务状态错乱 | 照抄 `runner.go:367-372`；单测覆盖 |
| R7 | 隧道序号/关闭语义 | server 10s 强拆 | 先声明保守 Capabilities，P3 再开新语义 |

## 2. 体积与静态链接风险（v2 新增，最容易翻车）

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| S1 | 误引 OpenSSL | 静态 1.5–3 MB，直接顶穿预算 | 产品构建禁用；`IMPLANT_CRYPTO_BACKEND=openssl` 仅开发预设，CI 加「产物里不得出现 `libssl`/`libcrypto` 符号」断言 |
| S2 | mbedTLS 默认配置过大（TLS1.2/DTLS/PSK/server 模式/错误字符串） | 300–800 KB | 自定义 `MBEDTLS_CONFIG_FILE`，只编 TLS1.3 client；关 `MBEDTLS_ERROR_C`、`MBEDTLS_SELF_TEST`；CI 记录体积趋势 |
| S3 | glibc 静态链接体积（当前 863 KB） | 超出 KB 目标 | Linux 生产用 musl-gcc / zig cc；CI 的默认 preset 设为 musl |
| S4 | MinGW `-shared` + `-static` 产出 ar 归档 | 产物不是 DLL | 工具链文件里对 SHARED 禁用 `-static`（已注释说明，Sliver 自身踩过：`binaries.go:222-227`） |
| S5 | Windows 动态 CRT 被 MSVC 属性页覆盖 | 产物依赖 `VCRUNTIME140` | `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` + `cppbuild` 导入表扫描（已实现） |
| S6 | `-flto` 与 `/GL` 下调试困难、个别库不兼容 | 构建失败难定位 | 提供 `IMPLANT_LTO=OFF` 的 debug preset；CI 两种都编 |

## 3. 许可

| 组件 | 许可 | 与 Sliver(GPLv3) 兼容 | 结论 |
|---|---|---|---|
| mbedTLS 3.6 | Apache-2.0 | 是 | **主选**（TLS1.3 + 密码学） |
| monocypher | CC0 / BSD-2 | 是 | 主选（Ed25519、BLAKE2b） |
| miniz | MIT | 是 | 主选（gzip） |
| zlib | zlib | 是 | miniz 的替代 |
| OpenSSL 3 | Apache-2.0 | 是 | 仅开发对拍 |
| wolfSSL | GPLv2-only / 商业 | **否**（与 GPLv3 冲突） | 排除（除非有商业授权） |
| BoringSSL | OpenSSL+ISC | 是 | 备选（体积仍偏大） |

**结论**：implant 整体 GPLv3；依赖只用上表「是」。

## 4. 工程风险

| # | 风险 | 对策 |
|---|---|---|
| E1 | 线程模型迁移引入竞态（Go channel → 有界队列） | `conn_generation` 代际号 + `closed` 原子标志；所有等待点可打断；TSan 进 CI |
| E2 | PTY / tar+gzip 打包被低估 | P1 单独排 3 人日；先小文件后大文件 |
| E3 | `GenerateCpp` 与官方 `Generate` 逐渐分叉 | 只允许在「编译后端」一层分叉；其余逐句镜像；PR 模板要求贴出与 `rpc-generate.go` 的 diff |
| E4 | `services.proto` 改了忘跑 `make pb` | CI 加「proto 与 pb.go 一致」检查（`make pb` 后 `git diff --exit-code`） |
| E5 | 上游 Sliver 协议漂移 | 固定上游 commit；升级时先跑金标向量 + 字段号断言 |
| E6 | WSL 从 Windows 调起时的 PATH/代理告警 | 统一 `wsl --exec env -u PATH bash -lc`；CI 用原生 ubuntu runner |
| E7 | 调试困难（implant 崩了没栈） | Debug preset 保留符号；可选 minidump/core；日志分级 |

## 5. 待拍板的开放问题

1. **musl 作为 Linux 默认**：是否接受在 WSL 里装 `musl-tools` 并用 musl-gcc 作为默认 Linux 工具链（否则 Linux 产物 ~800 KB）？
2. **proto 重新生成**：本机没有 protoc，`services.proto` 的 `GenerateCpp` 声明需要在你那台具备 protobuf 工具链的环境跑 `make pb`——由我改 proto 文本，还是你本地生成后提交？
3. **CLI 开关**：`--cpp` 加在 `generate` 子命令（走 `GenerateCpp`），还是新增 `generate-cpp` 子命令？
4. **mbedTLS 引入方式**：git submodule（版本可控、构建慢）还是 vcpkg/apt（快、版本漂移）？
5. **P-521 取舍**：若 mbedTLS 最小配置下 P-521 体积代价明显，是否接受「只在需要时编入 P-521」（服务端证书曲线随机，可能需要全开）？
6. **P4 的注入/CLR/BOF** 是否进本期（≈20 人日，建议单独立项）？
7. **CI 归属**：GitHub Actions（需 runner 成本）还是本地 `scripts/matrix.ps1` + 手动触发？
