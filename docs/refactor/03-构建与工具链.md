# 03 构建与工具链

> 目标：一份源码，三套编译器（MSVC / MinGW-w64 / Clang），两个平台（Windows / Linux），四种产物（exe / dll / so / shellcode 转换输入），
> 全部由 CMake 驱动，配置在 configure 阶段注入。

---

## 1. 目标矩阵

| # | 宿主 | 编译器 | 目标平台 | 产物 | 状态（本次实测） |
|---|---|---|---|---|---|
| B1 | Windows 物理机 | MSVC 19.44（VS2022） | windows/x64 | exe / dll | ✅ 可用（`vcvars64.bat` 存在） |
| B2 | WSL Ubuntu（2） | gcc 15.2 | linux/x64 | exe / so | ✅ 编译器可用，**缺 libssl-dev/zlib**，需 apt 补 |
| B3 | WSL Ubuntu | clang 18+ | linux/x64 | exe / so | ⚠️ 未安装，需 `apt install clang` |
| B4 | WSL Ubuntu | MinGW-w64 | windows/x64 | exe / dll | ⚠️ 未安装，需 `apt install mingw-w64` |
| B5 | Windows 物理机 | clang-cl + lld-link | windows/x64 | exe / dll | ⚠️ 未安装（VS 组件「C++ Clang 工具」或 LLVM 官方包） |
| B6 | Windows 物理机 | LLVM MinGW（clang + lld，`--target=x86_64-w64-windows-gnu`） | windows/x64 | exe / dll | ⚠️ 可选 |

实测环境事实：
- `cmake 3.31.6`、`ninja`（VS 自带）、`git 2.x`、MSVC `14.44.35207`；
- WSL：`gcc 15.2.0`、`cmake 4.2.3`、`ninja`、`python3`；无 clang / mingw / openssl / mbedtls / libsodium 开发包；
- WSL 从 Windows 调起时会有 `localhost proxy` 与 `PATH` 翻译告警 → 统一用 `wsl -d Ubuntu --exec env -u PATH bash -lc '...'` 或专用脚本规避（见 §6）。

### 2.1 顶层 CMakeLists 关键结构

```cmake
cmake_minimum_required(VERSION 3.25)
project(sliver_implant LANGUAGES C CXX)

list(APPEND CMAKE_MODULE_PATH ${CMAKE_CURRENT_LIST_DIR}/cmake)
include(SliverOptions)      # 定义 IMPLANT_FORMAT / 特性开关 / 配置路径
include(SliverWarnings)

# 1) 核心静态库：协议/加密/传输/平台（不含 main 与 secrets）
add_library(sliver_core STATIC ${CORE_SRCS})
target_include_directories(sliver_core PUBLIC include ${GEN_DIR})

# 2) secrets 单独成库，只被 core/config.c 链接一次
add_library(sliver_secrets STATIC ${GEN_DIR}/implant_secrets.c)
target_link_libraries(sliver_core PRIVATE sliver_secrets)

# 3) 按 IMPLANT_FORMAT 生成产物
if(IMPLANT_FORMAT STREQUAL "exe")
  add_executable(implant ${ENTRY_SRCS})
elseif(IMPLANT_FORMAT STREQUAL "shared")
  add_library(implant SHARED ${ENTRY_SRCS})
  target_compile_definitions(implant PRIVATE IMPLANT_BUILD_DLL=1)
endif()
target_link_libraries(implant PRIVATE sliver_core)
```

### 2.2 选项（`SliverOptions.cmake`）

| 选项 | 默认 | 说明 |
|---|---|---|
| `IMPLANT_FORMAT` | `exe` | `exe` / `shared` / `static`（供 shellcode 转换） |
| `IMPLANT_FEATURE_MTLS/HTTP/DNS/WG/PIVOT` | 按 `config.json` 推导 | 决定编译哪些 transport TU |
| `IMPLANT_PLATFORM_ABI` | 自动 | `win-x64` / `linux-x64` … |
| `SLIVER_CONFIG_JSON` | 空 | server 生成的配置；为空时用 `config/dev.json` |
| `IMPLANT_DEBUG_LOG` | OFF | 打开日志与断言（对应 `{{if .Config.Debug}}`） |
| `IMPLANT_SECRETS_XOR` | ON | secrets.c 是否构建期 XOR |
| `IMPLANT_STATIC_CRT` | ON | MSVC `/MT`；MinGW `-static-libgcc -static-libstdc++` |
| `IMPLANT_LTO` | OFF | 体积优先时开 |
| `IMPLANT_STRIP` | ON（Release） | 符号裁剪 |

## 3. 三编译器差异处理

| 主题 | MSVC | MinGW-w64 | Clang / clang-cl | 处理方式 |
|---|---|---|---|---|
| 导出宏 | `__declspec(dllexport)` | 同 | 同 | `IMPLANT_API` 宏 + 生成 `.def` 兜底 |
| 运行时库 | `/MT`（静态 CRT） | `-static-libgcc -static-libstdc++` | 同 MSVC（clang-cl） | `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` |
| 线程 | Win32 原语 | Win32 原语（**不用 winpthreads**） | 同 | `platform/win32/*.c` |
| 网络 | `ws2_32` | `-lws2_32` | 同 | `target_link_libraries(... ws2_32)` 仅在 WIN32 |
| POSIX 头 | 无 | 有（但 implant 走 Win32 分支） | 无 | `#ifdef _WIN32` 只出现在 `platform/` |
| 告警 | `/W4` | `-Wall -Wextra` | `-Wall -Wextra -Wconversion` | 分级：MSVC 关闭 4100/4189 |
| 入口 | `main` / `DllMain` | 同 | 同 | `IMPLANT_FORMAT` 决定 |
| 子系统 | `/SUBSYSTEM:WINDOWS` + `WIN32_EXECUTABLE` | `-mwindows` | 同 MSVC | 由 `IMPLANT_GUI` 选项控制 |
| 路径脱敏 | `/pathmap:${SRC}=/src` | `-ffile-prefix-map=${SRC}=/src` | 同 | 全预设默认开启 |
| 静态链接陷阱 | — | **`-shared` + `-static` 会产出 ar 归档**（Sliver 踩过，`binaries.go:222-227`） | — | SHARED target 上禁止 `-static`；CMake 里显式 `target_link_options(... -Wl,--no-static)` 或不用该组合 |

## 4. 产物形态与入口

| `IMPLANT_FORMAT` | 入口 | 产物 | 备注 |
|---|---|---|---|
| `exe` | `src/entry/main.c` → `sliver_run()` | `implant.exe` / `implant` | GUI 子系统由 `IMPLANT_GUI` 控制 |
| `shared` | Windows `DllMain`（`CreateThread` 启动，**绝不在 DllMain 内做网络**）；Linux `__attribute__((constructor))` | `implant.dll` / `implant.so` | 导出符号名由 `IMPLANT_ENTRY_SYMBOL`（默认 `StartW`）统一喂给 `.def`、构造函数与 shellcode 转换器 |
| `static` | 供外部链接 | `libimplant.a` | 对应 Go 的 `c-archive` 形态 |
| shellcode | 由外置步骤把 `exe`/`shared` 转成 `.bin` | `implant.bin` | 一期不在 C 工程内实现转换；列出 donut/malasada 等价工具接口即可 |

## 5. 配置注入流程

```
config.json (server 生成，全量注入项见 01 §6)
   │
   ├─ cmake -DSLIVER_CONFIG_JSON=... -P cmake/SliverConfigGen.cmake
   │     ├─ implant_build_config.h   # #define / static const
   │     ├─ implant_profile.h        # HTTP profile 表
   │     └─ implant_secrets.c        # 密钥/证书/URL（可选 XOR）
   └─ 生成 IMPLANT_BUILD_SEED（每次 configure 随机）
```

`SliverConfigGen.cmake` 用 `file(READ ...)` + `string(JSON ...)`（CMake ≥3.19 内建）解析，不引入 Python 依赖；
字符串转义（PEM 多行、`"`、反斜杠）统一用 `[[[ ... ]]]` 原始字符串包裹，避免 C 转义坑。

**金标向量生成**（M0 任务）：写一个 Go 小工具 `tools/vecgen`（放 server 侧或独立 module），复用 `server/cryptography`、`server/c2` 的签名逻辑，
输出 `implant-cpp/tests/vectors/*.json`。每次协议相关改动都重跑并 diff。

## 6. 构建脚本

### 6.1 `scripts/build-msvc.ps1`

```powershell
param([string]$Preset = "msvc-x64", [string]$Config = "", [string]$ConfigJson = "")
$vs = "D:\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"
cmd /c "`"$vs`" >nul && cmake --preset $Preset -DSLIVER_CONFIG_JSON=`"$ConfigJson`" && cmake --build --preset $Preset"
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 6.2 `scripts/build-wsl.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail
# 用 --exec 规避 Windows PATH 翻译告警
wsl -d Ubuntu --exec env -u PATH bash -lc '
  set -euo pipefail
  cd /mnt/d/GOPATH/src/C2/sliver/implant-cpp
  cmake --preset wsl-gcc -DSLIVER_CONFIG_JSON="$1"
  cmake --build --preset wsl-gcc -j"$(nproc)"
' _ "${1:-config/dev.json}"
```

## 7. CI 设计（GitHub Actions）

| Job | runner | 工具链 | 断言 |
|---|---|---|---|
| `msvc` | windows-2022 | MSVC | `dumpbin /exports` 仅含入口符号；`/dependents` 无 CRT 动态库；子系统正确 |
| `mingw`（WSL 内） | windows-2022 | `x86_64-w64-mingw32-g++` | `objdump -p` 导出表与 `msvc` 一致（diff） |
| `clang-cl` | windows-2022 | clang-cl + lld | 同上，与 msvc 导出表 diff |
| `linux-gcc` | ubuntu-24.04 | gcc | `readelf -d` 无外部 `DT_NEEDED`（静态预设）；`.init_array` 含入口 |
| `linux-clang` | ubuntu-24.04 | clang | 同上 + `-fsanitize` 单测通过 |
| `vectors` | ubuntu-24.04 | Go + CMake | 金标向量双向校验（Go→C、C→Go） |
| `artifact-hygiene` | 任意 | shell | `strings` 断言不含绝对路径/`bishopfox`/测试域名；同参数两次构建 sha256 **不同**；体积上限 |

产物卫生断言的意义：等价于 Go 侧的 `-trimpath` + `garble -literals -seed=random`（`server/gogo/go.go:146-180`、`server/generate/binaries.go:159-172`），
Sliver 自己**没有**这些断言（见 05 §4），C 侧要把它们变成可失败的门禁。

| 目标 | 命令 | 结果 |
|---|---|---|

| Windows dll（MSVC） | `cmake --preset msvc-x64-dll && cmake --build --preset msvc-x64-dll` | ✅ `bin/implant.dll` 12,800 B，`dumpbin /exports` 仅 `StartW` |
| Linux exe（WSL gcc） | `cmake --preset wsl-gcc && cmake --build --preset wsl-gcc` | ✅ `bin/implant`，`--self-test` 通过，`ctest` 1/1 通过 |
| Linux so（WSL gcc） | `cmake --preset wsl-gcc -DIMPLANT_FORMAT=shared -B build/wsl-gcc-so` | ✅ `bin/implant.so` 22,584 B，`nm -D` 导出 `StartW` |
| 配置注入 | 改 `config/dev.json` 后重新 configure | ✅ 头部/ secrets 随之变化；`implant_build_config.h` 与 `implant_secrets.c` 生成正确 |

踩坑记录（已修，留作后续参考）：
1. `-std=c11 -Wpedantic` 下 `clock_gettime/nanosleep` 需要 `_POSIX_C_SOURCE=200809L`（`src/platform/posix/thread.c` 顶部已定义）；
2. MinGW/MSVC 下必须先 `<winsock2.h>` 再 `<windows.h>`，否则 `WSADATA` 未定义；
3. 静态库被 `SHARED` 目标链接时必须 `POSITION_INDEPENDENT_CODE ON`（否则 `relocation R_X86_64_PC32 ... recompile with -fPIC`）；
4. MSVC 的 `/pathmap:` 需要先开 `/experimental:deterministic`，否则被忽略；
5. VS 生成器不认 `CMAKE_BUILD_TYPE`（用 `--config Release`），preset 里对 msvc 不要依赖该变量。

结论：**M0 可以在当前机器直接开工**（MSVC 出 exe/dll + WSL gcc 出 exe/so 四条链路已实测通过），
clang 与 mingw 两条链路通过 §6.3 的 apt 安装补齐即可，不阻塞。
